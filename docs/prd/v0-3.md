# v0.3 — a guard for Claude Code, and easier hand-offs for agents

Plan for the release after 0.2.2. Rules: `.claude/CLAUDE.md`. Steps: `docs/steps.md` (S-37 onward). Research: `docs/research.md` (R-6 and R-10 to R-13 answered). The earlier plan is `docs/prd/card-v2.md`.

## Playback (confirmed by Abhishek 2026-11-07)

"lets build these": the five candidates that were ranked in the register, in this order:

1. A guard for Claude Code (two hooks, and a command that switches them on and off).
2. `--json` results, so an agent can read what happened without parsing sentences.
3. `keyprompt setup`: read the names a project needs and ask for the missing ones on one card.
4. A names-only activity log.
5. `keyprompt mcp`, last, because it needs research (R-6) and a decision about a dependency first.

The first four need no new dependency. One step is one PR, and I stop after each.

## Goal

Narrow one of the limits `SECURITY.md` lists under "What it does not protect against": the agent can read a saved key straight from the OS password store, and "nothing stops it" (the limit bug B-2 made it state). In Claude Code, with the guard installed, the obvious direct reads will be refused. Then make keyprompt easier for agents to drive (S-41 to S-45).

## For whom

Abhishek first (D-3), then solo developers who use Claude Code.

## Success — acceptance sentences

- **G1 (S-38).** WHEN Claude Code is about to run a Bash command (and a PowerShell one, once R-12 says what that tool sends) whose text runs one of the reads under "What counts as a direct read" THEN the guard SHALL deny it, with a reason that tells the agent to run its command through `keyprompt run` instead.
- **G1b (S-38).** WHEN a command only mentions those words without running them (searching keyprompt's own source with `git grep find-generic-password`, an `echo`, a commit message) THEN the guard SHALL print nothing and exit 0, so Claude Code's normal permission flow decides.
- **G2 (S-38).** WHEN a message to Claude looks like it contains an API key THEN the guard SHALL tell the person and the agent which kind of key it looks like, and SHALL NOT repeat the text, write it anywhere, send it anywhere or block the message (D-12).
- **G3 (S-39).** WHEN the person runs `keyprompt install-guard` and confirms THEN `~/.claude/settings.json` SHALL gain the guard's two hook entries, every other setting and hook in it SHALL keep its value, and a second run SHALL add nothing. WHEN they run `keyprompt uninstall-guard` THEN only those entries SHALL go.
- **G4 (S-40).** WHEN the guard ships THEN `SECURITY.md` and the README SHALL say what it refuses, that it fails open, and that it covers Claude Code only, and the words "nothing stops it" SHALL be changed so they stay literally true.
- **J (S-41, S-47).** WHEN `set`, `has`, `list` or `delete` is given `--json` THEN it SHALL emit one JSON result on stdout with command, status, names and exitCode, including failures, never values or raw error text; a failure SHALL also carry a message in keyprompt's own words that says why, without anything keyprompt did not write itself; the exit codes and output without the flag SHALL stay unchanged.
- **F (S-42).** WHEN `keyprompt setup` runs in a folder whose `.env.example` (or the file named with `--from`) lists names THEN it SHALL open one card for the first 12 of those names that are not saved yet, in the file's order, with every box optional; SHALL NOT ask for a name that is already saved; SHALL report which names were saved, left empty, already saved and not asked yet, and the `keyprompt run` line for the saved ones; and SHALL never show, return or store anything that follows `=` in the file. WHEN the file's name does not say it is a template (`.env`, `.env.local`) THEN setup SHALL refuse with exit 2 before reading it.
- **L (S-43).** WHEN `set`, `setup` or `run` saves a value, `run` hands names to a command, `delete` removes a saved name, or a card ends with Later, Cancel or a timeout THEN keyprompt SHALL add one line to `activity.jsonl` beside the catalog with the time, the event, the keyprompt command, the names, the exit code and the folder (and for `run`, the program's name), and SHALL NOT write a value, a reason, an environment, a command's arguments or its output; the file SHALL keep only the newest 1,000 lines; `keyprompt log` SHALL show the newest 50; and a log that cannot be written SHALL NOT change the command's result.
- **M (S-45).** WHEN an MCP client starts `keyprompt mcp` and calls `request_secret` with fields THEN keyprompt SHALL open one card for them, wait for the person, and answer with `set --json`'s names-only result; WHEN it calls `check_secrets` THEN it SHALL answer which names are saved; no answer SHALL ever hold a value or the card's URL, stdout SHALL carry only JSON-RPC messages, and keyprompt SHALL add no dependency.

## What counts as a direct read (S-38 settles the exact list, R-12)

The guard blocks command text that runs one of these, and nothing else:

- **macOS:** `security find-generic-password` with `-w` or `-g` (the two options that print the value), or `security dump-keychain -d`, when it names the `keyprompt` service or a saved name. keyprompt saves each item with service `keyprompt` and account NAME (`src/store/macos.mjs`), so the account alone also finds it.
- **Linux:** `secret-tool lookup` or `secret-tool search` (which prints values, R-12) naming the `keyprompt` service or a saved name (`src/store/linux.mjs`).
- **Windows:** `Get-StoredCredential`, or CredRead through `Add-Type`, naming a target that starts with `keyprompt:` or a saved name (`src/store/windows.mjs`, R-12). `cmdkey` cannot show a password, so it goes through.

Saved names come from the catalog (`src/catalog.mjs`), which holds names only. The guard never reads a value.

## How the guard works (from R-10)

Claude Code runs a command we register before it runs a Bash or PowerShell tool call, and before it handles a message. The command gets JSON on stdin and answers with JSON on stdout.

- **`keyprompt guard pre-tool-use`** reads `tool_input.command`. For a direct read it answers `hookSpecificOutput.permissionDecision: "deny"` with a reason Claude sees. Otherwise it prints nothing and exits 0, which leaves Claude Code's normal permission flow alone.
- **`keyprompt guard user-prompt-submit`** reads `prompt`. If it looks like a key, it names the kind, never the text, in a `systemMessage` for the person and `hookSpecificOutput.additionalContext` for the agent. This hook also runs on messages the person did not type (a `/loop` turn, a background subagent's report, a message from another session), so the words say "this message", never "you pasted".
- **`keyprompt install-guard`** and **`uninstall-guard`** add and remove the two entries in `~/.claude/settings.json` (or wherever R-11 says Claude Code reads it). The PreToolUse matcher is `Bash|PowerShell`. The handler runs the absolute path of the `node` that ran `install-guard` (or a link on PATH that points at it, which outlives a Homebrew upgrade, R-13), with `args` holding the absolute path of `bin/keyprompt.mjs` and the event name, so no shell and no `.cmd` shim is involved. It has a short `timeout` (10 seconds) instead of the 600-second default. It refuses to install from npx's temporary cache, whose folder can be deleted at any time (R-13). A settings file that is not valid JSON is left alone and the command stops. The file is written to a temporary file and then renamed, so a crash never leaves half a file.

## Honest limits (S-40 puts these in `SECURITY.md` and the README)

- **It fails open.** If the guard cannot start, crashes, prints invalid JSON or times out, Claude Code lets the command through and shows a hook error (R-10). Removing the Node version or the global install the hook points at does the same; running `install-guard` again fixes it.
- **It reads command text.** It refuses the obvious direct reads. A script, an encoded command or another tool (Read, Edit) can still reach the store or the settings, and an agent that can edit `~/.claude/settings.json` can remove the guard. It is a guardrail, not a wall. The words are "refuses the obvious direct reads", never "Claude Code cannot read your keys".
- **A warning cannot take a key back.** By the time a warning shows, the message has already gone to Claude. Only a block keeps it from Claude, and even a blocked message stays in Claude Code's local transcript and prompt history (R-10).
- **It is Claude Code only**, and only where the person has run `install-guard`.

## Not doing in this release

- No guard for agents other than Claude Code. R-10 covers Claude Code's hooks only; nothing equivalent has been checked for Codex or Cursor.
- No hooks on tools other than Bash and PowerShell.
- No editing of project settings files, and no change to `~/.claude/settings.json` without the person's confirmation.
- No telemetry and no network calls (invariant 6). The guard sends nothing anywhere.

## JSON results (S-41)

Scope chosen from the recommendation when Abhishek said "next" on 2026-11-07: `set`, `has`, `list`, `delete`, including failures; `run` is separate. No new dependency. The remaining field and stream choices are implementation decisions below.

- One newline-terminated JSON object on stdout, including failures. Common fields: command (one of the four supported commands, or null when not recognized), status, names (validated names only), exitCode. Progress for an open card stays on stderr. No raw error message, arguments, reason, value, browser URL or catalog contents in a result.
- Status maps to the existing codes: saved/listed/deleted (0), error (1), invalid_usage (2), missing (3), cancelled (4), timed_out (5), deferred (6). `has` uses saved/missing. `list` reports sorted catalog names, not proof they still exist in the store.
- A failure also carries `message` (S-47, D-18): the sentence text mode prints after `keyprompt:`, except that a typed argument (an unknown option or hint, an invalid name) and a store helper's own error line are left out of it. An error keyprompt did not expect gets the fixed sentence "keyprompt hit an unexpected error. Its text is left out of JSON results; run the same command without --json to see it." In JSON mode stderr still gets no copy of the message.
- A successful `set` names only filled boxes and also reports replaced and empty arrays. A failed operation names its valid requested fields, or an empty array when arguments could not be parsed. A catalog update failure after a save or delete adds warnings: ["catalog_not_updated"] without changing the operation's status or code.
- `--json` is recognized only among keyprompt's own options, never as a value of `--reason`/`--by`, or after `--`. On unsupported commands, including `run`, it returns invalid_usage before any side effect. Help and version stay text when combined with a supported command; alone with `--json` they return invalid_usage.
- README and agent-skill examples follow in a separate docs step, as S-41 originally planned. CLI help describes the flag now.

## Setup (S-42)

`keyprompt setup [--from FILE] [--reason TEXT] [--by TEXT] [--json]`, from D-19. What `run` and `set` do not already do: setup finds the names itself, asks before any command runs, and skips names that are saved.

- **Which file.** `.env.example` in the current folder, or the file `--from` names. The file's own name (not its folder) must contain example, sample, template, schema or dist as a word between dots, dashes or underscores (`.env.example`, `example.env`, `.env.local.example`, `.env.dist`). Anything else, `.env` and `.env.local` included, is refused with exit 2 before it is opened. A missing file and a file over 1 MB are refused the same way. Messages never repeat the path given with `--from`.
- **Which names.** Lines of the form `NAME=...`, with an optional `export ` in front. Blank lines and `#` comments are skipped. Only the text before `=` is kept; a value that opens a quote and runs over several lines is passed over to its closing quote, so none of its lines is mistaken for a name. A name that is not a keyprompt name (capital letters, digits and _) is not used: its line number is reported, never its text. Each name counts once.
- **The card.** The names not saved in the OS password store, in the file's order, at most 12, every box optional and hidden. Save needs at least one value, as with `set`. Remember is always on. `--reason` and `--by` work as with `set`; setup writes no reason of its own, because the card shows a reason as the agent's words.
- **The report.** Saved now, left empty, already saved (not asked), not asked yet (over 12), lines not read, then `Use them with: keyprompt run NAMES -- <command>` for every name that is saved now, in the file's order. When nothing is missing, no card opens and the report says so. Later, Cancel and a timeout end it as they end `set` (exit 6, 4, 5).
- **JSON.** `{"command":"setup","status":"saved","names":[saved now],"exitCode":0,"replaced":[],"empty":[left empty],"warnings":[],"skipped":[already saved],"remaining":[not asked yet],"ignoredLines":[line numbers]}`. `replaced` is always empty, because saved names are not asked; it is there so the result has `set`'s shape. A failure has S-41's shape; its `names` are the names on the card, or empty when it fails before a card opens.
- **Not doing.** Hints from the file (a PEM key needs `keyprompt set NAME:multiline`); reading `.env`, `.env.local` or the code to find names; writing anything into the project; more than one card at a time.

## Activity log (S-43)

From D-20. `src/activity.mjs` writes and reads `activity.jsonl` in the catalog's folder (`~/.keyprompt`, or `KEYPROMPT_HOME`).

- **A line.** One JSON object: `{"time":"<ISO 8601, UTC>","event":"saved","command":"set","names":["A_KEY"],"exitCode":0,"folder":"<the folder keyprompt ran in>"}`. A `run` line adds `"program":"python"`: the program's own name, without its folder or any argument. `event` is `saved`, `run`, `deleted`, `deferred` (Later), `cancelled` or `timed_out`; `exitCode` is what that action ended with (0 for a save or delete, 6, 4 or 5 for a card that ended without a save, the command's own code for `run`); `command` is the keyprompt command that did it.
- **When.** A save writes a line once the card has saved at least one value with Remember on (Remember unticked saves nothing, so only the `run` line follows). A `run` line is written when the command ends, with the time it started and only the names it was given; a run that gives no name a value writes none. A `delete` writes one only when a value was removed. `has`, `list`, `log`, `demo` and the guard write nothing, and neither does a usage error.
- **Size.** After each line, the file is cut to the newest 1,000. Two keyprompt processes cutting it at the same moment can lose one line.
- **Silent.** Nothing is printed when a line is written, and a log that cannot be written (a folder that cannot be made, a full disk) is left as it is: the command's output and exit code do not change.
- **`keyprompt log [--json]`.** The newest 50 lines, oldest first, in local time: "Saved A_KEY (set), in /folder", "Gave A_KEY to python, which exited with 0, in /folder", "Deleted A_KEY", "The person chose Later for A_KEY (set)", "The person cancelled the card for ...", "Nobody filled in the card for ...", then where the file is. `--json` gives `{"command":"log","status":"listed","names":[the names in the lines shown],"exitCode":0,"entries":[the lines shown]}`. A line that is not one keyprompt wrote whole (edited by hand, cut off) is left out.
- **Not doing.** A command's arguments, its output, its environment or a value; a way to turn the log off (not asked for; deleting the file empties it); a log of `has` or `list`.

## MCP server (S-45)

From D-22 and R-6. `src/mcp.mjs` speaks the protocol; `mcpTools()` in `src/cli.mjs` holds the two tools.

- **Protocol.** JSON-RPC 2.0, one message per line on stdin and stdout; stdout carries nothing else, and keyprompt's own lines (the "opened a secure card" line) go to stderr. Handshake versions 2025-11-25, 2025-06-18, 2025-03-26 and 2024-11-05: `initialize` gets the version asked for when it is one of these, otherwise 2025-11-25. `ping`, `tools/list` and `tools/call` are answered; any other method, including the 2026-07-28 probe `server/discover`, gets "method not found" (-32601). Per the 2026-07-28 stdio binding, that is the answer that makes a client which speaks both eras fall back to `initialize`. A request the client cancelled gets no answer. A line over 1 MB is not read.
- **`request_secret`** takes `fields` (1 to 12 FIELDs, hints as in `set`) and an optional `reason`. It works like `set`: one card, Save needs a value, a saved name says Replace. It answers with `set --json`'s result as text, and from 2025-06-18 also as `structuredContent`. Cancel, a timeout and Later are answers (`isError: false`); a bad argument or a store failure is an error (`isError: true`), with a message that never repeats what was sent. One card at a time: a second call while a card is open is refused. The card's "who is asking" is the client's own name, as the agent's words. The card's URL is never in an answer: keyprompt opens the browser itself.
- **A list that names nothing** (`[" "]`, `[","]`) is a usage error for both tools, before any store read or card (B-20, S-51).
- **`check_secrets`** takes `names` (1 to 12) and answers `{"command":"has","status","names","exitCode","saved","missing"}`.
- **The activity log** marks a save made through `request_secret` with the command `mcp`.
- **Not doing.** URL-mode elicitation (R-6: today it would reach only clients that can already run `keyprompt`, Codex declines a non-https URL, and the spec's "pre-authenticated URL" rule is not settled); a tool that runs a command or returns a value; the 2026-07-28 per-request protocol; an installer.
